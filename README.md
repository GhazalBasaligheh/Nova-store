# فروشگاه نوا (NOVA Store)

ویترین عمومی فروشگاه آنلاین نوا که برای چالش فنی توسعه‌دهنده فرانت‌اند (UI) نوا ساخته شده است.
این پروژه یک اپلیکیشن دوزبانه (فارسی راست‌به‌چپ و انگلیسی چپ‌به‌راست) با Next.js و App Router است که تم روشن و تیره،
کاتالوگ محصولات با فیلتر سمت کاربر و سبد خرید ماندگار دارد و داده‌هایش را از [FakeStoreAPI](https://fakestoreapi.com) می‌گیرد.

پنل مدیریت همراه این پروژه در مخزنی جداگانه قرار دارد: [NOVA Admin](https://github.com/GhazalBasaligheh/Nova-admin).

## امکانات

- **صفحه اصلی:** بخش معرفی (Hero) با دکمه «مشاهده محصولات»، دسته‌بندی‌ها به‌صورت چیپ، شبکه محصولات با کارت‌های هم‌اندازه
  (تصویر، دسته‌بندی، عنوان، امتیاز، قیمت، افزودن به سبد)، جستجو، مرتب‌سازی (پیشنهادی، قیمت، نام، امتیاز) و
  صفحه‌بندی (۶ محصول در هر صفحه). تمام وضعیت لیست در URL نگه داشته می‌شود، پس قابل اشتراک‌گذاری است و با رفرش از بین نمی‌رود.
- **هدر:** لوگو، لینک‌های اصلی، منوی دسته‌بندی، جستجو، تغییر زبان، تغییر تم و آیکون سبد خرید با شمارنده زنده.
  منوی فشرده در موبایل.
- **صفحه سبد خرید:** یک ردیف برای هر محصول با تصویر، قیمت واحد، کنترل تعداد (هرگز کمتر از ۱)، جمع ردیف و حذف؛
  خلاصه سفارش؛ خالی کردن سبد؛ حالت سبد خالی. سبد در `localStorage` ذخیره می‌شود.
- **خبرنامه:** فیلد ایمیل با اعتبارسنجی Formik و Yup.
- **فارسی (پیش‌فرض، راست‌به‌چپ) در `/` و انگلیسی (چپ‌به‌راست) در `/en`**، با اعداد و قیمت‌های بومی‌سازی‌شده.
- **تم روشن و تیره** که در کوکی ذخیره می‌شود و از همان اولین نمایش درست رندر می‌شود (بدون پرش رنگ).
- **حالت‌های صریح بارگذاری، خطا (با تلاش دوباره)، خالی و موفقیت** در لیست محصولات، سبد خرید، افزودن به سبد و خبرنامه.
- **سئو:** متادیتای جداگانه برای هر زبان، Open Graph، لینک‌های canonical و `hreflang`، و فایل‌های `sitemap.xml` و `robots.txt`.

## فناوری‌ها

| موضوع        | انتخاب                                                       |
| ------------ | ------------------------------------------------------------ |
| فریم‌ورک     | Next.js 16.4 (App Router)، React 19، TypeScript 5.9 (strict) |
| چندزبانگی    | next-intl 4                                                  |
| استایل       | styled-components 6 با رندر سمت سرور                         |
| state سراسری | Zustand 5 (سبد خرید)، Context API (تم)                       |
| HTTP         | Axios با یک نمونه مشترک                                      |
| فرم‌ها       | Formik + Yup                                                 |
| فونت         | وزیرمتن (فونت متغیر میزبانی‌شده در پروژه، مجوز SIL OFL)      |
| کیفیت کد     | ESLint (پیکربندی Next، قانون `no-explicit-any`)، Prettier    |

نسخه همه وابستگی‌ها در `package.json` دقیقاً ثابت شده است.

TypeScript روی نسخه 5.9 ثابت شده و نه 7.x؛ چون 7.0 یک نسخه اصلی جدید است و ابزارهای Next 16 هنوز با آن سنجیده نشده‌اند.

## راه‌اندازی

### پیش‌نیازها

- Node.js **نسخه 20.9 یا جدیدتر** (توسعه با Node 22.13 انجام شده است)
- npm نسخه 10 یا جدیدتر

### نصب و اجرا

```bash
git clone https://github.com/GhazalBasaligheh/Nova-store.git
cd Nova-store
npm install
cp .env.example .env.local
npm run dev
```

آدرس http://localhost:3000 (فارسی) یا http://localhost:3000/en (انگلیسی) را باز کنید.

### بیلد نسخه production

```bash
npm run build
npm run start
```

## متغیرهای محیطی

فایل `.env.example` را به `.env.local` کپی کنید. همه متغیرها تنظیمات عمومی (`NEXT_PUBLIC_*`) هستند، نه اطلاعات محرمانه؛
چون داخل کد سمت کاربر قرار می‌گیرند. اگر یکی از آن‌ها وجود نداشته باشد یا نامعتبر باشد، برنامه همان ابتدا با پیامی واضح
متوقف می‌شود (`src/utils/env.ts`).

| متغیر                           | کاربرد                                                                        | نمونه                      |
| ------------------------------- | ----------------------------------------------------------------------------- | -------------------------- |
| `NEXT_PUBLIC_API_BASE_URL`      | آدرس پایه FakeStoreAPI برای نمونه Axios                                       | `https://fakestoreapi.com` |
| `NEXT_PUBLIC_SITE_URL`          | آدرس اصلی سایت برای متادیتا، sitemap و robots                                 | `http://localhost:3000`    |
| `NEXT_PUBLIC_USD_TO_TOMAN_RATE` | نرخ ثابت **فقط برای نمایش آزمایشی** دلار به تومان (بخش [واحد پول](#واحد-پول)) | `200000`                   |

## ساختار پوشه‌ها

ساختار مطابق بخش ۴-۴ سند چالش است. تفاوت‌ها زیر نمودار فهرست و توضیح داده شده‌اند.

```
src/
├── api/                  # AxiosInstance + ApiError (مدیریت متمرکز خطا)
├── app/
│   ├── [locale]/
│   │   ├── layout.tsx    # <html lang dir>، فونت، providerها، متادیتا
│   │   ├── page.tsx      # صفحه اصلی (کامپوننت سروری: بارگذاری کاتالوگ و رندر بخش‌ها)
│   │   ├── cart/page.tsx # سبد خرید (noindex)
│   │   ├── not-found.tsx # صفحه ۴۰۴ بومی‌سازی‌شده
│   │   ├── error.tsx     # error boundary صفحه‌ها
│   │   └── [...rest]/    # هر مسیر ناشناخته را به not-found می‌فرستد
│   ├── globals.css       # فقط ریست‌های ثابت
│   ├── robots.ts
│   └── sitemap.ts
├── assets/
│   ├── Fonts/            # فونت متغیر وزیرمتن + مجوز
│   ├── Icons/            # کامپوننت‌های آیکون SVG
│   └── Images/           # (خالی؛ بخش پیش‌فرض‌ها)
├── components/           # بخش‌های سطح صفحه، هر بخش یک پوشه
│   ├── Cart/  Footer/  Header/  Hero/  Newsletter/  ProductSection/
│   │                     # هر بخش: کامپوننت + فایل .styles.ts؛ ProductSection یک پوشه hooks/ هم دارد
├── context/              # ThemeContext، رجیستری SSR برای styled-components، توکن‌های تم
├── dictionary/           # fa.json و en.json (پیام‌های next-intl)
├── i18n/                 # مسیریابی next-intl + ناوبری وابسته به زبان (بخش تفاوت‌ها)
├── modals/               # (خالی: مودالی لازم نشد)
├── requests/             # توابع درخواست API (محصولات، بارگذار کاتالوگ سمت سرور)
├── shared/
│   ├── ui/               # UI قابل استفاده مجدد: Button، Badge، Container، Pagination، Rating، ...
│   └── hooks/            # هوک‌هایی که بیش از یک بخش استفاده می‌کند: usePrice، useCategoryLabel
├── storage/              # store سبد خرید با Zustand + ابزارهای hydration
├── types/
│   └── enums/            # Locale، Direction، Theme، SortKey، ApiErrorKind، CategorySlug
├── utils/                # منطق مستقل از UI: parseProductQuery، filterSortPaginate، formatPrice، env، seo، routes، ...
├── validations/          # اسکیماهای Yup
├── global.d.ts           # تایپ پیام‌ها و زبان‌های next-intl
├── i18n.ts               # پیکربندی هر درخواست next-intl (محلی که سند چالش خواسته است)
└── proxy.ts              # proxy در Next 16 (همان middleware سابق): مسیریابی زبان
```

**تفاوت‌ها با سند چالش و دلیل آن‌ها**

- **پوشه `src/i18n/` در کنار `src/i18n.ts`.** سند چالش `src/i18n.ts` را خواسته که پیکربندی هر درخواست next-intl در آن است.
  next-intl به یک تعریف مسیریابی (مشترک بین `proxy.ts`، لینک‌ها و متادیتا) و ابزارهای ناوبری وابسته به زبان هم نیاز دارد.
  قرار دادن این‌ها در `i18n.ts` کد مخصوص سرور را وارد proxy و باندل کاربر می‌کرد، بنابراین در `src/i18n/routing.ts` و
  `src/i18n/navigation.ts` قرار گرفته‌اند.
- **توکن‌های تم در `context/theme/`** و کنار ThemeContext که از آن‌ها استفاده می‌کند قرار دارند.
- **مسیرهای متمرکز در `utils/routes.ts`** هستند، چون ساختار Store پوشه `Routes/` ندارد.
- **هوک‌ها جدا از کامپوننت‌های UI در پوشه‌های `hooks/` هستند.** سند چالش پوشه hooks ندارد. قاعده: هوکی که فقط یک بخش
  استفاده می‌کند در `hooks/` همان بخش است (`components/ProductSection/hooks/useProductQuery.ts`) و هوکی که بیش از یک بخش
  استفاده می‌کند در `shared/hooks/` (`usePrice`، `useCategoryLabel`). منطقی که هوک‌ها به آن تکیه دارند به‌صورت توابع خالص
  در `utils/` است.
- **`shared/` به `ui/` و `hooks/` تقسیم شده است**، تا کامپوننت‌های پایه و هوک‌ها کنار هم قاطی نشوند.
- **استایل‌ها کنار کامپوننت و در فایل جداگانه `<Name>.styles.ts` هستند** (مثلاً `Header.tsx` و `Header.styles.ts`)، پس فایل
  کامپوننت فقط منطق و ساختار است. اجزای پایه‌ای که خودشان فقط یک styled component هستند (`Button`، `Badge`، `Container`،
  `Skeleton`) همان‌طور در یک فایل مانده‌اند.

## معماری

### مسیریابی و چندزبانگی

- `proxy.ts` میدل‌ور next-intl را با زبان‌های `fa` (پیش‌فرض) و `en` و تنظیم `localePrefix: 'as-needed'` اجرا می‌کند:
  فارسی در `/`، انگلیسی در `/en`، و `/fa` به `/` هدایت می‌شود.
- **تشخیص زبان مرورگر خاموش است** (`localeDetection: false`). آدرس `/` همیشه فارسی است و کاربر با دکمه هدر زبان را
  عوض می‌کند؛ این دکمه مسیر فعلی و پارامترهای جستجو را حفظ می‌کند.
- `[locale]/layout.tsx` ویژگی‌های `lang` و `dir` (`rtl` / `ltr`) را روی `<html>` تنظیم می‌کند.
- زبان درخواست در `src/i18n.ts` با `next/root-params` خوانده می‌شود (Next.js 16.3 به بعد). این روش جایگزین
  `requestLocale` و `setRequestLocale` شده که در next-intl نسخه 4.14 منسوخ اعلام شده‌اند.
- همه متن‌های رابط کاربری از `dictionary/*.json` می‌آیند و هیچ متن فارسی یا انگلیسی مستقیم در JSX نیست. پیام‌ها
  تایپ‌شده هستند (`global.d.ts`)، بنابراین کلید ناموجود در زمان کامپایل خطا می‌دهد.
- مسیر ناشناخته (مثلاً `/en/abc`) صفحه ۴۰۴ بومی‌سازی‌شده را با همان هدر، فوتر، زبان و تم نشان می‌دهد
  (`[locale]/[...rest]` + `not-found.tsx`)، و `error.tsx` خطاهای غیرمنتظره رندر را داخل همان چیدمان می‌گیرد.
- اعداد، امتیازها، شماره صفحه‌ها و قیمت‌ها برای زبان فعال قالب‌بندی می‌شوند (ارقام فارسی در `fa`).
- **داده محصولات فقط انگلیسی است.** FakeStoreAPI عنوان و توضیحات را به انگلیسی برمی‌گرداند؛ این متن‌ها در نسخه فارسی
  همان‌طور نمایش داده می‌شوند و برای صفحه‌خوان‌ها با `lang="en"` علامت‌گذاری شده‌اند. نام دسته‌بندی‌ها از طریق دیکشنری
  ترجمه می‌شود.

### استایل و تم

- styled-components با رجیستری استایل سمت سرور (`context/StyledComponentsRegistry.tsx`) و گزینه کامپایلر SWC
  یعنی `styledComponents`، تا HTML سرور از ابتدا استایل‌دار باشد و نام کلاس‌ها هنگام hydration یکسان بمانند.
- یک فایل توکن تایپ‌شده (`context/theme/tokens.ts`): پالت‌های روشن و تیره (سرمه‌ای اصلی، نارنجی تأکیدی، پس‌زمینه کرم)،
  فاصله‌ها، گردی گوشه‌ها، سایه‌ها و نقاط شکست موبایل‌محور (768 / 1024 / 1280).
- راست‌به‌چپ و چپ‌به‌راست با ویژگی‌های منطقی CSS (`margin-inline`، `padding-inline`، `inset-inline-end` و ...) و
  ویژگی `dir` مدیریت می‌شود. آیکون‌های جهت‌دار (فلش‌های صفحه‌بندی) در حالت راست‌به‌چپ قرینه می‌شوند.
- **تم (Context API):** فقط روشن یا تیره. انتخاب کاربر در کوکی `nova-theme` ذخیره می‌شود و layout آن را در سرور
  می‌خواند، پس اولین نمایش همان رنگ درست را دارد؛ بدون پرش رنگ و بدون ناهمخوانی hydration. این کوکی یک ترجیح نمایشی
  غیرحساس است، پس `HttpOnly` نیست (سمت کاربر تغییرش می‌دهد).

### ارتباط با API

- `api/axiosInstance.ts` تنها نمونه Axios است: آدرس پایه از env، مهلت ۱۰ ثانیه، هدر `Accept` از نوع JSON.
- یک interceptor پاسخ، **هر** خطا را به یک `ApiError` تایپ‌شده با یک `kind` تبدیل می‌کند:

  | نوع       | معنی                                       |
  | --------- | ------------------------------------------ |
  | `network` | بدون پاسخ: پایان مهلت، خطای DNS، قطع اتصال |
  | `server`  | خطای 5xx                                   |
  | `client`  | سایر خطاهای 4xx                            |
  | `parse`   | پاسخ رسید اما ساختار مورد انتظار را نداشت  |

- توابع درخواست در `requests/products.ts` (`getProducts`، `getCategories`، `fetchCatalog`) داده تایپ‌شده
  (`types/product.ts`) برمی‌گردانند و بررسی می‌کنند که پاسخ‌های لیستی واقعاً آرایه باشند.
- تصاویر محصولات با `next/image` از آدرس `fakestoreapi.com/img/**` نمایش داده می‌شوند؛ این دامنه در `images.remotePatterns` فایل
  `next.config.ts` مجاز شده است.

### داده محصولات: رندر سمت سرور با کش

صفحه اصلی کاتالوگ را در سرور می‌گیرد، پس شبکه محصولات از همان ابتدا در HTML اولیه است (برای سئو و اولین نمایش).

1. `requests/catalogServer.ts` (فقط سمت سرور) محصولات و دسته‌بندی‌ها را بارگذاری می‌کند.
   - در صورت موفقیت، کاتالوگ **۱ ساعت در حافظه کش** می‌شود (`utils/ttlCache.ts`).
   - هر خطا به‌صورت `error` برگردانده می‌شود و **هرگز کش نمی‌شود**؛ پس درخواست بعدی دوباره سراغ API می‌رود.
2. `ProductSection` یکی از حالت‌های `ready` یا `error` را نمایش می‌دهد. در حالت خطا دکمه «تلاش دوباره» با `router.refresh()` رندر سروری را دوباره اجرا می‌کند و در این مدت اسکلتون نمایش داده می‌شود. اگر در حالت `ready` بعد از فیلتر هیچ نتیجه‌ای نباشد، حالت خالی نمایش داده می‌شود.

**بده‌بستان‌ها:**

- کش حافظه مخصوص هر پردازه سرور است: بین چند نمونه مشترک نیست و با ری‌استارت پاک می‌شود. برای یک دموی تک‌سروری
  مناسب است؛ در استقرار چندنمونه‌ای باید از یک کش مشترک استفاده کرد.
- پس از پایان یک ساعت، اولین درخواست باید منتظر پاسخ API بماند.

قابلیت `cacheComponents` / `'use cache'` در Next عمداً خاموش مانده است: سند چالش آن را نخواسته و نحوه نوشتن داده پویا
(کوکی تم) و کش را تغییر می‌دهد.

### مدیریت state

| state                                   | محل                                      | دلیل                                             |
| --------------------------------------- | ---------------------------------------- | ------------------------------------------------ |
| سبد خرید                                | Zustand (`storage/cartStore.ts`)         | سراسری؛ بین نشان سبد در هدر و صفحه سبد مشترک است |
| تم                                      | Context API (`context/ThemeContext.tsx`) | تنظیم رابط کاربری در کل برنامه، طبق سند چالش     |
| جستجو، دسته‌بندی، مرتب‌سازی، صفحه       | کوئری URL (`?q=&category=&sort=&page=`)  | قابل اشتراک و ماندگار با رفرش                    |
| باز بودن منو، فیلدهای فرم، بازخورد دکمه | `useState` / Formik                      | مخصوص یک کامپوننت                                |

**جزئیات سبد خرید:**

- اکشن‌ها: `add`، `increment`، `decrement` (هرگز کمتر از ۱)، `remove`، `clear`. تعداد اقلام و جمع جزء با
  سلکتورها محاسبه می‌شوند و ذخیره نمی‌شوند.
- قیمت‌ها به **دلار** ذخیره می‌شوند و فقط هنگام نمایش تبدیل می‌شوند.
- با کلید `nova-cart` در `localStorage` ذخیره می‌شود و نسخه‌دار است (`version: 1`)، تا اگر ساختار `CartItem` بعداً عوض شد بتوان داده ذخیره‌شده قدیمی را مهاجرت داد. سبد خرید داده حساسی ندارد، پس طبق سند چالش استفاده از
  `localStorage` قابل قبول است.
- **ایمنی hydration:** سرور نمی‌تواند `localStorage` را بخواند، پس state ذخیره‌شده فقط بعد از mount بارگذاری می‌شود
  (`skipHydration` + `CartHydrator`). تا آن زمان نشان سبد عددی نشان نمی‌دهد و صفحه سبد اسکلتون نمایش می‌دهد، بنابراین HTML
  سرور و اولین رندر سمت کاربر همیشه یکسان هستند.

خواندن وضعیت لیست از URL در `utils/parseProductQuery.ts` و فیلتر، مرتب‌سازی و صفحه‌بندی در
`utils/filterSortPaginate.ts` است؛ هر دو تابع خالص هستند. مقادیر نامعتبر در URL به‌جای ایجاد خطا به مقدار پیش‌فرض برمی‌گردند.

تغییر فیلتر، مرتب‌سازی و صفحه با `router.replace` انجام می‌شود، پس برای هر کلیک یک ورودی جدید در تاریخچه مرورگر ساخته
نمی‌شود و دکمه «عقب» به صفحه قبلی می‌رود، نه به فیلتر قبلی. جستجوی هدر از `router.push` استفاده می‌کند، چون یک اقدام
آگاهانه است و برگشت به جستجوی قبلی مفید است. پس از جستجو و پس از تغییر صفحه، صفحه به ابتدای لیست محصولات اسکرول
می‌شود تا نتیجه دیده شود.

### فرم و اعتبارسنجی

فرم خبرنامه از Formik با یک اسکیمای Yup در `validations/newsletter.ts` استفاده می‌کند. پیام‌های اسکیما کلیدهای دیکشنری
هستند، پس اسکیما به زبان وابسته نیست. خطاها برای صفحه‌خوان‌ها اعلام می‌شوند و فیلد با `aria-invalid` علامت می‌خورد.

**هیچ endpoint ای برای خبرنامه وجود ندارد** (FakeStoreAPI چنین چیزی ندارد و بک‌اند خارج از محدوده است)، پس ارسال معتبر
فقط حالت موفقیت را نشان می‌دهد. هیچ چیزی ارسال یا ذخیره نمی‌شود.

### سئو

- عنوان `<title>` برای هر زبان (با الگوی `%s | NOVA Store`)، توضیحات، `metadataBase` از `NEXT_PUBLIC_SITE_URL`، و
  تگ‌های Open Graph (نام سایت، زبان `fa_IR` / `en_US` و زبان جایگزین، نوع، آدرس).
- آدرس canonical و جایگزین‌های `hreflang` (`fa`، `en`، و `x-default` که به فارسی اشاره می‌کند) در هر صفحه.
- `sitemap.xml` هر دو زبان صفحه اصلی را با جایگزین‌ها فهرست می‌کند. `robots.txt` اجازه خزش می‌دهد، سبد خرید را در هر
  زبان مسدود می‌کند و به sitemap اشاره می‌کند. صفحه سبد خرید `noindex` هم هست.
- تگ‌های معنایی `header` / `nav` / `main` / `footer` و فقط یک `h1` در هر صفحه.
- در ادغام `metadata` در Next، اگر صفحه `openGraph` خودش را تعریف کند، `openGraph` والد جایگزین (و نه ادغام) می‌شود؛
  بنابراین صفحه‌هایی که آدرس Open Graph اضافه می‌کنند از تابع مشترک `baseOpenGraph()` (`utils/seo.ts`) شروع می‌کنند.

## واحد پول

- نسخه انگلیسی **دلار** نشان می‌دهد که واحد خود API است (`$109.95`).
- نسخه فارسی **تومان** نشان می‌دهد که با **نرخ ثابت آزمایشی ۱ دلار = ۲۰۰٬۰۰۰ تومان** تبدیل، به تومان کامل گرد و با ارقام
  فارسی قالب‌بندی می‌شود (`۲۱٬۹۹۰٬۰۰۰ تومان`).
- **این نرخ فقط برای نمایش است و نرخ واقعی یا نرخ محیط production نیست.** مقدار آن از `NEXT_PUBLIC_USD_TO_TOMAN_RATE`
  خوانده می‌شود، پس بدون تغییر منطق برنامه قابل تغییر است (`utils/formatPrice.ts`).

## دسترس‌پذیری و واکنش‌گرایی

- چیدمان موبایل‌محور که در عرض‌های **360، 768، 1024 و 1280 پیکسل** در هر دو زبان روی صفحه اصلی و سبد خرید بررسی شده و
  هیچ اسکرول افقی یا هم‌پوشانی ندارد. شبکه محصولات: یک ستون زیر 480 پیکسل، دو ستون در تبلت، سه ستون در دسکتاپ.
- چیپ‌های دسته‌بندی در موبایل یک ردیف افقی هستند که با لمس یا با کشیدن ماوس (`useDragScroll`) اسکرول می‌شود و اسکرول‌بار
  ندارد؛ از اندازه تبلت به بعد در چند خط می‌شکنند.
- اهداف لمسی حداقل 44 پیکسل هستند. هر کنترل فقط‌آیکون یک `aria-label` ترجمه‌شده دارد. حاشیه فوکوس قابل مشاهده است.
- تعداد نتایج، بازخورد افزودن به سبد، تغییر تعداد و نتیجه فرم‌ها از طریق live region اعلام می‌شوند. حالت‌های بارگذاری از
  `aria-busy` استفاده می‌کنند.
- انیمیشن‌ها به `prefers-reduced-motion` احترام می‌گذارند.

## پیش‌فرض‌ها

- زبان پیش‌فرض فارسی است.
- قیمت‌ها در نسخه فارسی با نرخ ثابت آزمایشی به تومان نمایش داده می‌شوند (بخش [واحد پول](#واحد-پول)).
- لینک‌های راهنما، فروشگاه و شبکه‌های اجتماعی در فوتر، طبق اجازه سند چالش، موقت هستند.
- تصویری برای Hero ارائه نشده بود، پس از یک طرح تزئینی برند استفاده شده؛ بعداً می‌توان یک عکس در `assets/Images` قرار داد.
- منوی دسته‌بندی هدر از چهار نام دسته‌بندی تأییدشده API استفاده می‌کند تا بدون درخواست جداگانه رندر شود. چیپ‌های صفحه
  اصلی از لیست زنده دسته‌بندی‌ها استفاده می‌کنند.
- جستجو روی عنوان محصولات و نام دسته‌بندی‌ها انجام می‌شود.

که تسویه بخشی از این دمو نیست. صفحه جزئیات محصول به تعویق افتاده و ساخته نشده است.

## محدودیت‌های شناخته‌شده

- کش کاتالوگ در حافظه بین نمونه‌های مختلف سرور مشترک نیست (بخش بده‌بستان‌ها در بالا).
- تصویر Open Graph وجود ندارد، چون تصویر برندی ارائه نشده بود.
- sitemap تا زمانی که صفحه‌های محصول وجود نداشته باشند فقط صفحه اصلی (در هر دو زبان) را دارد.
- تست خودکار وجود ندارد؛ کیفیت با TypeScript سخت‌گیرانه، ESLint، Prettier، بیلدهای production و تست دستی در مرورگر
  بررسی شده است.
